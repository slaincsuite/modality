# Agent Note: 前端缺口驱动的后端补接口批次

Status: implemented

## Problem

前端完成真实接口接入后，仍有一批页面操作没有后端端点（SSO IdP 管理、通知接收人/订阅、飞书配置、用户安全子资源、策略目录与批量授权、工单类型与订阅回显等），同时暴露了若干联调缺陷（角色分页空参 500、工单通知保留字 500、回收站 BIGINT 比较错误、树接口只返回根节点、任务控制器条件注册顺序）。这些能力横跨多个业务模块，若不先定下跨模块取数与权限播种口径，各模块会各自直连他方表或互相依赖。

## Decision

2026-10-17 起按以下口径补齐（均为已发布现实）：

- **数据归属模块注册端点**：聚合他方数据的端点由数据归属模块实现，路径按产品语义放置（如 `/tenant/{id}/users` 由 upms 注册、`/upms/user/{id}/mfa` 由 auth 注册、`/upms/user/{id}/api-keys` 由 infra 注册），业务模块之间仍不互相依赖
- **重复消费的跨模块能力走 SPI**：`cn.slainc.core.spi.UserUsageProvider`（upms 实现，tenant 消费）与策略模块的 `PolicyGroupProvider` 作为「接口 + 模型」下沉，SPI 缺失时端点返回可解释的空值而非报错
- **新增端点沿用现有权限前缀并补种子**：`db/seed-admin.sql` 增加 29 个新权限码并写入平台租户行（id=1）；平台管理员按 `CROSS JOIN t_permission` 全量授权，重复执行幂等
- **直播监控取最小可用语义**：`t_live_stream` 直播源登记 + HTTP 健康探测 + 批量检测 + 统计；探测禁用重定向并拦截内网/回环/链路本地地址
- **缺省租户口径一致**：服务层取租户统一用 `TenantContext.getOrDefault()`，与 MyBatis 租户拦截器默认租户 1 的行为保持一致

## Alternatives considered

**为每项跨模块数据都新建 SPI**：接口与模型数量会迅速膨胀，而多数查询只服务单一页面；只在重复消费（租户用量、策略用户组）时下沉 SPI，其余由数据归属模块直接注册端点。

**让业务模块互相依赖**：违反分层硬约束，且会让模块无法独立引用；放弃。

**直播监控等待业务需求再实现**：前端已有监控入口且骨架长期空置，先交付可用的健康监控闭环，后续按业务替换探测语义。

**给管理员授予通配权限**：会绕开权限模型的可审计性；改为补种具体权限码并保持全量授权脚本幂等。

## Consequences

- 收益：前端所有现有页面均有真实端点支撑；权限种子在全新库验证通过（192 个权限码全部授予平台管理员）
- 代价：个别端点路径与模块包名不完全对应（数据归属优先），需要在评审时按本笔记解释
- 边界：通行密钥仅管理注册元数据、未实现完整 WebAuthn 断言校验；飞书通讯录同步暂不写入 upms 用户表；策略边界与通知接收人的外部投递通道仍需后续迭代
